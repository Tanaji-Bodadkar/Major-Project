THE LIVE PIPELINE

One monitoring cycle

Device telemetry and model predictions refresh continuously while the dashboard is open.

↻ REPEATS
  1. 01⌁

    Read device signals

    Windows reports CPU load and frequency, memory, disk and network activity. GPU data is included when the device exposes it.

    OS telemetry · ~5 sec
  2. 02◇

    Prepare features

    The app converts signals into the model’s expected units and feature order. Missing GPU data stays missing and is flagged.

    Validated inputs
  3. 03ƒ

    Estimate power

    The prototype ML model estimates watts from the current telemetry. Its training targets are synthetic, so real-world accuracy is not established.

    Estimate · not a meter
  4. 04∫

    Accumulate session energy

    While a session is active, estimated watts are integrated over elapsed time to produce Wh and kWh totals.

    Session-based · resets on start
  5. 05↗

    Estimate carbon impact

    Session energy is combined with grid carbon intensity to estimate operational Scope 2 CO₂e. If live data is unavailable, the dashboard labels its static fallback.

    Source shown beside intensity
Then the cycle starts again. The dashboard keeps a rolling view of recent telemetry and estimates.
WHAT YOU SEE

Live signals and estimates are different

Live telemetry

CPU, memory, disk, network and available GPU readings collected from the operating system.

Model estimate

Power, energy and CO₂e are calculated outputs. They are experimental until validated against appropriately scoped measurements.

Carbon intensity

May come from a live provider or the clearly identified static fallback. Its update rate follows that source.
